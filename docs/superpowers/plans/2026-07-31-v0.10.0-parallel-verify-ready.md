# v0.10.0 Preparation Implementation Plan

> **For agentic workers:** Implement this plan task-by-task as separate commits
> on one feature branch. Do not create task sub-branches; Git ref path collisions
> make `feature/<parent>/task-*` branch names invalid once the parent branch
> exists, and the overhead is not useful for this release.

**Goal:** Prepare v0.10.0 by adding optional, unattended-capable parallel spec
verification to `spar-ready`, before a plan branch or spar plan state exists.
The verifier should improve plan quality without changing the core `spar-fight`
review loop.

**Architecture:** `spar-ready` gains a neutral `verify_spec` option. When it is
requested, the command resolves the spec and runs a spar-owned verifier before
creating `.claude/spar-plan.local.md` or checking out the plan branch. The
verifier fans out two read-only checks, one Claude-family and one Codex-family,
with the spec content embedded in each prompt so workers do not need an
untracked `.claude/` file. It writes durable artifacts under `reviews/`, plus a
small `.claude/` working summary only after verification has finished. If the
verification finds unresolved ambiguity, contradiction, or a missing oracle,
`spar-ready` stops cleanly before branch/state creation.

The existing standalone `parallel-verify` skill is useful precedent, but v0.10.0
must not depend on it. That skill requires user approval of the brief and is not
unattended-compatible. This feature ships a spar-owned verification path whose
brief is deterministic and can run in unattended mode.

**Tech Stack:** POSIX-ish bash 3.2, markdown command/skill documents, read-only
Claude/Codex runner generation shaped like the existing plan-review/reviewer
runners, pure-bash tests with CLI stubs. Live Orca/agent behavior is covered by
manual release-gate smoke tests.

## Global Constraints

- The core fight loop does not change. No changes to reviewer convergence,
  judge/matcher routing, round caps, final sweep, or Stop-hook enforcement.
- Verification happens before the plan branch checkout and before
  `.claude/spar-plan.local.md` is written.
- `.claude/spar-plan-spec.txt` remains a post-verification working copy. It is
  git-excluded and must not be the input that parallel workers need to read.
- Verification prompts embed the captured spec content directly. If the spec was
  supplied as a committed file path, the prompt may also name that path as
  context, but the worker must be able to verify from the prompt alone.
- Durable verification evidence lives in `reviews/`, not only in `.claude/`.
  `.claude/` files are working state and may be deleted by `spar-cancel`.
- `--unattended --verify-spec` is supported. The verifier does not ask the user
  to approve a brief. If it cannot produce a clean/usable result, it blocks
  before planning rather than fabricating completion.
- Existing untracked user work, including `docs/posts/`, must not be touched.

**Interfaces:**
- `spar-ready-resolve.sh` adds a sixth tab-separated field:
  `<mode>\t<reviewer>\t<unattended>\t<plan_review>\t<verify_spec>\t<spec>`.
- `verify_spec=true` only when `--verify-spec` is passed.
- `--no-verify-spec` sets `verify_spec=false` and is accepted for explicitness.

until the resolver semantics are deliberately changed. The current resolver
strips a leading `-- ` before flag parsing, so `-- --no-plan-review build` is

- [ ] **Step 2: Add caller/document tests**

### Task 3: Add the Cross-Comparison Gate and Move Branch Creation After It

**Commit:** `feat(ready): gate planning on spec verification`

**Files:**
- Create: `plugins/spar/commands/spar-spec-verify-check.sh`
- Modify: `plugins/spar/commands/ready.md`
- Modify: `adapters/codex/skills/spar-ready/SKILL.md`
- Test: `tests/test_spec_verify_check.sh` (new)
- Test: `tests/test_ready_ingest.sh`
- Test: `tests/test_codex_adapter.sh`

**Interfaces:**
- `spar-spec-verify-check.sh <verify-id>` reads both durable verifier reports and
  writes `.claude/spar-spec-verify.md`, a concise working summary for plan
  writing.
- It exits:
  - `0` when both reports are clean or findings are non-blocking and summarized.
  - `1` when either report is missing, invalid, blocked, or raises unresolved
    ambiguity/contradiction/missing oracle.
  - `2` on usage/unsafe ids.
- If the check exits non-zero, `spar-ready` stops before creating a branch or
  `.claude/spar-plan.local.md`.
- If verification passes or is skipped, `spar-ready` proceeds to create
  `.claude/spar-plan-spec.txt`, create the plan branch, write plan state, and
  continue existing planning/plan-review behavior.

- [ ] **Step 1: Add checker tests**

Cover clean/clean, findings with accepted summary, blocked, missing file,
invalid marker, symlink artifact, and unsafe id.

- [ ] **Step 2: Add branch-timing tests**

Extract or statically assert the ready documents run the verification section
before `git checkout -b` and before writing `.claude/spar-plan.local.md`.

- [ ] **Step 3: Implement the checker**

Keep the first version conservative: any `SPEC-VERIFY: FINDINGS` with ambiguity,
contradiction, or missing-oracle wording blocks. Non-blocking observations can be
summarized into `.claude/spar-spec-verify.md` for the planner.

- [ ] **Step 4: Update Claude `ready.md`**

When `RDY_VERIFY_SPEC=true`, run the two generated verifier runners, then run the
checker. This is command-owned behavior, not a call to the standalone
approval-based `parallel-verify` skill.

- [ ] **Step 5: Update Codex `spar-ready` skill**

Mirror the same shell-driven verifier flow. Keep the Codex skill wording clear
that this is the spar-owned verifier path and is unattended-compatible.

- [ ] **Step 6: Update plan-writing instructions**

Both ready surfaces must read `.claude/spar-spec-verify.md` if present and
include a short verification context section in the generated plan. The task
extractor must not depend on that section.

- [ ] **Step 7: Verify**

Run:

```bash

bash tests/test_codex_adapter.sh
```

- [ ] **Step 8: Mutation checks**

Confirm tests fail if branch creation occurs before verification, if missing
