# v0.10.0 Parallel Verify Ready Implementation Plan

> **For agentic workers:** Implement this plan task-by-task. The parent branch is
> `feature/v0.10.0-parallel-verify-ready`; each task is implemented on its own
> sub-branch named `feature/v0.10.0-parallel-verify-ready/task-<n>-<slug>`, then
> merged back into the parent branch after its tests pass.

**Goal:** Add an optional pre-plan verification phase to `spar-ready`, using the
local `parallel-verify` skill on both Claude and Codex seats before a plan is
written, and make the result part of the planning context without moving the
deterministic shell engine into skill invocation.

**Architecture:** The shell layer learns only a neutral `verify_spec` flag and
state fields. It never invokes `parallel-verify`: skill invocation is
adapter-specific, so the Claude command and the Codex skill each call their local
`parallel-verify` through that host's normal skill mechanism. Both adapters write
the normalized verification result to `.claude/spar-spec-verify.md`; planning
must read that file if present, stop on unresolved ambiguity or contradiction,
and otherwise incorporate its findings into the implementation plan.

**Tech Stack:** POSIX-ish bash 3.2, markdown command/skill documents, pure-bash
tests with CLI stubs. `parallel-verify` itself depends on Orca orchestration and
committed inputs, so automated tests cover flag/state/document behavior while the
release gate covers live fan-out.

## Global Constraints

- The core fight loop does not change. No changes to reviewer convergence,
  judge/matcher routing, round caps, final sweep, or Stop-hook enforcement.
- Shell helpers parse and record verification intent only. They must not call
  Claude skills, Codex skills, Orca, or agent CLIs for `parallel-verify`.
- Both seats stay mirrors in behavior but not in invocation wording: Claude
  instructions use Claude's skill mechanism; Codex instructions use Codex's skill
  mechanism.
- `parallel-verify` requires committed inputs and an Orca ADE runtime. If those
  preconditions are not met, `spar-ready --verify-spec` stops before planning
  with a clear message instead of silently skipping verification.
- `--no-verify-spec` is the default-compatible escape hatch. Existing
  `spar-ready` behavior must remain unchanged unless verification is requested.
- Any plan generated after verification must cite `.claude/spar-spec-verify.md`
  in its context section and carry concrete task steps for accepted findings.
- Existing untracked user work, including `docs/posts/`, must not be touched.

### Task 1: Parse and Persist `verify_spec`

**Sub-branch:** `feature/v0.10.0-parallel-verify-ready/task-1-verify-flag`

**Files:**
- Modify: `plugins/spar/commands/spar-ready-resolve.sh`
- Modify: `plugins/spar/commands/ready.md`
- Modify: `adapters/codex/skills/spar-ready/SKILL.md`
- Test: `tests/test_ready_resolve.sh`
- Test: `tests/test_ready_ingest.sh`
- Test: `tests/test_codex_adapter.sh`

**Interfaces:**
- `spar-ready-resolve.sh` adds a sixth tab-separated field:
  `<mode>\t<reviewer>\t<unattended>\t<plan_review>\t<verify_spec>\t<spec>`.
- `verify_spec` is `true` only when `--verify-spec` is passed.
- `--no-verify-spec` sets `verify_spec=false` and is accepted for explicitness.
- Repeating either verification flag, or passing both, is an error.
- The free-form spec remains last.
- Plan state gains:
  - `spec_verify: required|skipped`
  - `spec_verify_path: .claude/spar-spec-verify.md`

the literal flag after `--`.

Assert both ready surfaces destructure the new field and write the two new state
fields. Include a behavioral check that the final spec field still receives the
actual spec text.

- [ ] **Step 3: Implement resolver parsing**

Follow the existing `--no-plan-review` parsing style. Keep the spec last and
preserve tabs/newlines inside the spec body by relying on positional field order,

- [ ] **Step 4: Update both ready setup blocks**

### Task 2: Add Adapter-Specific `parallel-verify` Instructions

**Sub-branch:** `feature/v0.10.0-parallel-verify-ready/task-2-adapter-invocation`

**Files:**
- Modify: `plugins/spar/commands/ready.md`
- Modify: `adapters/codex/skills/spar-ready/SKILL.md`
- Test: `tests/test_ready_ingest.sh`
- Test: `tests/test_codex_adapter.sh`

**Interfaces:**
- When `spec_verify=required`, each adapter must run its local
  `parallel-verify` skill before writing the plan.
- The verification brief targets `.claude/spar-plan-spec.txt` and asks for
  read-only validation of ambiguity, contradictions, missing acceptance criteria,
  code/spec mismatch, risky unstated assumptions, and implementation-order traps.
- The final verification result is normalized into `.claude/spar-spec-verify.md`.
- If verification cannot run because Orca is unavailable, orchestration is off,
  or relevant inputs are uncommitted, `spar-ready` stops before plan writing and
  reports the reason.

Assert the Claude command names `parallel-verify` as a Claude-side skill action
and the Codex skill names `parallel-verify` as a Codex-side skill action. The
test should also assert no shell block attempts to run `parallel-verify`,
`orca orchestration`, or either agent CLI directly from a shared helper.

- [ ] **Step 2: Add mirror tests for common result contract**

Assert both adapters require `.claude/spar-spec-verify.md` as the normalized
result path and both tell the planner to read it before planning.

- [ ] **Step 3: Update Claude `ready.md`**

Add a section between setup and plan writing:

1. If `spec_verify=skipped`, continue.

   contradiction, or missing oracle.
